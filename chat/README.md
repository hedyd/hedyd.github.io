# Resume chat

A Cloudflare Worker that answers `POST /api/chat` with Workers AI on the Free plan. The site in `../ui` calls it from the chat box.

The prompt is generated by `scripts/build-resume.mjs` from `../ui/src/data/` (resume, about and projects JSON) before every `wrangler dev` and `wrangler deploy`, so updating a project updates the chat too.

## Local development

```sh
npm install
npx wrangler login
npm run dev        # http://localhost:8787/api/chat (uses real Workers AI neurons)
npm run typecheck
```

To use it from the local site:

```sh
cd ../ui
PUBLIC_CHAT_URL=http://localhost:8787/api/chat npm run dev
```

`http://localhost:4321` is already in `ALLOWED_ORIGINS`.

## Configuration (`wrangler.jsonc`)

- `MODEL`: the Workers AI text model. Pick one that's free on the Workers Free plan.
- `ratelimits`: 5 questions a minute per IP.
- `ALLOWED_ORIGINS`: sites allowed to call the chat (CORS).

The Free plan's 10,000 neurons a day is a hard cap. Past it, the chat shows a "resting until tomorrow" message until 00:00 UTC.

## Deploy

The **Deploy Portfolio** workflow in `.github/workflows/astro.yml` deploys this Worker and builds the site. In the repo's **Settings → Secrets and variables → Actions**, it needs:

| Name | Kind | Where to get it |
| --- | --- | --- |
| `CLOUDFLARE_API_TOKEN` | Secret | Cloudflare dashboard → My Profile → API Tokens → Create Token → "Edit Cloudflare Workers" template |
| `CLOUDFLARE_ACCOUNT_ID` | Secret | Cloudflare dashboard → Workers & Pages (Account ID in the sidebar), or `npx wrangler whoami` |
| `PUBLIC_CHAT_URL` | Variable | `https://hedyd-chat.<your-subdomain>.workers.dev/api/chat`. The subdomain is shown under Workers & Pages, and `wrangler deploy` prints the full URL |

The site build fails on purpose if `PUBLIC_CHAT_URL` is missing.
